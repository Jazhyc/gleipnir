\section{Background and related work}
\label{sec:background}

\subsection{Monitoring agent actions}
\label{sec:background-monitoring}

\paragraph{Monitors in AI control.}
AI control studies how to deploy an AI agent safely even if the agent tries to cause harm~\citep{greenblatt2023ai}.
To test this, control evaluations give the agent a \emph{main task}, the work that a user asked for~\citep{kutasov2025shade,kaufman2025basharena}.
An agent that attacks also has a \emph{side task}: a harmful objective that it pursues in secret while it works on the main task.
A \emph{monitor} guards against such an agent.
It reads what the agent did and rates how suspicious the actions look.
In the trusted monitoring protocol of Greenblatt et al., this monitor is a weaker model that is trusted not to cause harm, and humans audit the actions that it rates highest.
Because human time is limited, the audit covers only a small share of the actions.
The monitor is therefore useful only if it rates agents with a side task above almost all honest agents.
The training data and the benchmarks in this report follow the same design.

\paragraph{Monitors in production.}
Coding agents already use such monitors in production.
In the auto mode of Claude Code~\citep{anthropic2026auto} and the auto-review of Codex~\citep{openai2026autoreview}, a separate model approves or blocks an action before it runs.
This model takes the place of the human who would otherwise approve the action.
When it blocks an action, the agent must find another approach, and after repeated blocks it stops and asks the user for permission.
A false positive is therefore costly: it blocks a harmless action, and repeated false positives halt autonomous work until the user responds.
In addition, the monitor runs before each reviewed action, so its latency delays the action and its inference cost adds to the cost of the agent.
A monitor in production thus needs a low false-positive rate, low latency and low cost.

\subsection{Trained monitors and their evaluation}
\label{sec:background-sinha}

\paragraph{Trained action-only monitors.}
\citet{sinha2026training} train open-weight models as monitors, from Qwen3.5-4B up to Kimi~K2.6, and our work builds on their setup.
Their monitors are \emph{action-only}: the monitor reads the visible trajectory of the agent, which consists of the user messages, the messages of the agent and the tool outputs.
It does not read the private reasoning or the activations of the agent, and we keep this restriction because both may become unreliable in future models.
A model that reasons in its latent space leaves no reasoning to read~\citep{korbak2025chain}, and activations can be reshaped to evade the monitors that read them~\citep{bailey2024obfuscated}.
The training set has 8,688 such trajectories, half of them benign, from five sources: STRIDE and Gloom~\citep{storf2026constitutional}, CoT-Red-Handed~\citep{arnav2025cot}, BashArena~\citep{kaufman2025basharena} and BashBench~\citep{bhatt2025ctrlz}.
The training targets are inspired by deliberative alignment~\citep{guan2024deliberative}.
A teacher model reads each trajectory with a written specification of scheming and writes a rationale that ends in a suspicion score from 0 to 10.
The monitor is trained to reproduce this output, so it writes a rationale before its score.

\paragraph{Evaluation suite and metric.}
Sinha et al.\ select checkpoints on a validation set that is built like STRIDE and Gloom.
They measure generalization on six out-of-distribution (OOD) benchmarks, which play no part in training or selection: AgentDojo~\citep{debenedetti2024agentdojo}, CUA-SHADE-Arena~\citep{kale2025reliable}, IaC~\citep{controlarena2025iac}, MLE-Sabotage~\citep{ward2025ctrl}, Rogue Eval~\citep{roger2024rogue} and SHADE-Arena~\citep{kutasov2025shade}.
Their metric is pAUROC@20: the area under the ROC curve for false-positive rates up to 20\%, normalized so that a perfect monitor scores 1.
They report its unweighted mean over the six benchmarks, Mean-OOD, together with the inference cost per 1,000 evaluations.
We reuse their training trajectories, OOD suite, metric and cost axis and compare with their reported scores, but change the monitor output and training target (Section~\ref{sec:method}).
