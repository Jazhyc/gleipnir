\section{Background and related work}
\label{sec:background}

\paragraph{Monitors in AI control.}
AI control studies how to deploy an AI agent safely even if the agent tries to cause harm~\citep{greenblatt2023ai}.
Control evaluations describe such an agent with two tasks~\citep{kutasov2025shade}.
The \emph{main task} is the work that the user asked for.
The \emph{side task} is a harmful objective that the agent pursues in secret while it works on the main task.
An honest agent has only the main task.
A \emph{monitor} reads what the agent did and rates how suspicious it looks.
In the trusted monitoring protocol of Greenblatt et al., the monitor is a weaker model that is trusted not to cause harm.
Humans audit the actions with the highest ratings.
Human time is limited, so the audit covers only a small share of the actions.
The monitor must therefore rate an agent with a side task above almost all honest agents.
The training data and the benchmarks in this report follow this design.

\paragraph{Monitors in production.}
Coding agents in production already use monitors.
In the auto mode of Claude Code~\citep{anthropic2026auto} and the auto-review of Codex~\citep{openai2026autoreview}, a separate model approves or blocks an action before it runs.
The monitor takes the place of the human who would otherwise approve the action.
A blocked action returns to the agent with the reason, and a human is asked only after repeated blocks.
A false positive interrupts the agent, as it spends human time in an audit.
Each reviewed action also waits for the monitor and pays for it.
A monitor in production therefore needs a low false-positive rate, a short response time and a low cost.
