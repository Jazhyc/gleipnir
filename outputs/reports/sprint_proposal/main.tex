\section{The problem: synchronous monitoring with a minimal safety tax}
The strongest AI control protocols are \emph{synchronous}: a trusted monitor scores each action an untrusted agent
proposes \emph{before} it executes, so a suspicious step can be blocked, resampled or escalated before it does harm.
This puts the monitor on the critical path of every agent step for every user. Its latency is added to each action and
its compute scales with the whole deployment. Frontier models are good monitors but too slow and expensive to run on
every step, so in practice one either monitors asynchronously (after the damage) or pays a large \emph{safety tax}.
A small monitor with frontier-level quality removes that trade-off: one GPU serves many concurrent agents, and the
per-action overhead is a small fraction of the agent's own inference cost.

\begin{minipage}[t]{0.50\textwidth}
\vspace{0pt}
\textbf{Gleipnir} trains small open-weight monitors for scheming, sabotage, deception and other control-relevant
behaviour in agent trajectories. The core recipe is \emph{binary-logit distillation}: a strong teacher's probability on
the decision token (\texttt{0}\,|\,\texttt{1}) becomes a soft target for a LoRA student that emits that single token.
With no generated rationale, a monitor call is one prefill; Gleipnir 4B scores a $\sim$4K-token trajectory in a median
0.15\,s on one B200 in unoptimised BF16. On the out-of-distribution suite of Sinha et al.\ (never used for selection),
Gleipnir 4B is the cheapest point on the cost--performance frontier (cost is the standard proxy, as latency varies widely across providers), and Gleipnir 27B surpasses its own teacher at
1/14 of the cost. \textbf{The sprint's goal is to move the 4B towards the 27B's quality at the 4B's cost.}

\section{Sprint plan \,(deliverable: Gleipnir v1 model release + technical report)}
\phase{Week 1: make the 4B much better, using Gleipnir 27B as an intermediate teacher.}
\begin{itemize}
  \item \textbf{Teacher-assistant distillation} (Kimi K3 $\rightarrow$ Gleipnir 27B $\rightarrow$ 4B). The 27B shares the
        4B's exact 248K-token vocabulary and model family, is now a stronger monitor than Kimi, and is cheap enough to
        relabel freely. The unadapted 27B was a \emph{worse} teacher than Kimi ($-1.9$ ID points), so the gain must come
        from the trained intermediate.
  \item \textbf{Richer supervision channels.} (i)~Full-vocabulary KL at the decision position. A first probe diagnostic
        finds the non-decision tail adds little over the binary margin (+0.04 ID / +0.7 OOD points), so this gets one
        controlled arm rather than a sweep. (ii)~Soft auxiliary targets such as the \emph{index of the harmful action},
        giving the student grounded evidence about \emph{where} the misbehaviour is, which also helps human auditors.
  \item Recipe and checkpoint choices are frozen on the held-out ID set; OOD is read once, at the end.
\end{itemize}
\phase{Week 2: find the blind spots and evaluate on benchmarks the project has never touched.}
\begin{itemize}
  \item \textbf{Adversarial attacks on the final monitors.} Because the score is a single logit margin, white-box
        attacks are straightforward: gradient-guided token optimisation (GCG-style) restricted to text an agent controls
        (its messages, comments and tool arguments), with embedding-space attacks as an upper bound. Then test whether
        the attacks transfer to black-box settings, to the 27B and to frontier monitors. Report attack success against
        edit budget and categorise the blind spots found.
  \item \textbf{Fresh benchmarks.} One-shot evaluation of the frozen release checkpoints on MonitoringBench and SleightBench
        (unseen throughout the project), with metrics and baselines fixed before scoring.
  \item \textbf{Release.} Model cards, weights, evaluation code and the technical report.
\end{itemize}

\section{Where Neel's input would help most}
\begin{itemize}
  \item \textbf{Attack threat model.} White-box gradient attacks are the easiest to run, but a scheming agent will not
        have gradients. Which attacker (white-box, transfer, LLM-rewriter, latent) would give results the control
        community finds convincing, and is a white-box blind-spot map still valuable as a worst-case bound?
  \item \textbf{Convincing benchmarks.} Beyond MonitoringBench and SleightBench, which held-out monitoring evaluations
        would the community find most convincing for a performance--cost claim?
  \item \textbf{Interpretability and scope.} Which mechanistic analyses of the monitor (e.g.\ what drives its suspicion
        score) would most strengthen the report, and what to cut if two weeks proves tight.
\end{itemize}

\section{Completed earlier in the exploration phase (included in the final report and release)}
\begin{itemize}
  \item \textbf{Inference optimisation.} Prefill-only B200 serving with FP4/MXFP8 kernels: up to 1.6$\times$ throughput
        for the 4B and 2.2--2.3$\times$ for the 27B across 4K--1M-token contexts over BF16. When a growing
        trajectory is re-scored after every action, prefix caching makes monitoring a 1M-token agent session
        12.9$\times$ faster than re-processing the full history each time.
  \item \textbf{Quantisation-aware distillation (QAD)} so that low-precision deployment copies keep BF16 ranking quality.
  \item \textbf{Serving-time ablation of injection-triggered suspicion.} Monitors flag harmless code once
        monitor-directed injection or jailbreak text is present. Removing the responsible residual-stream direction at
        inference time cuts these false alarms to below 0.5\%, with no retraining.
\end{itemize}
