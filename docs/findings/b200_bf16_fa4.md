# FlashAttention 4 screen on the packed BF16 B200 recipe

Date: 2026-10-04. Initial screen: rejected at the eager packing parity gate;
no FA4 optimizer updates. Continuation: explicitly authorized by the user after
reviewing the approximately 8% gradient difference. The matched timing screen
uses a separate 10% learning-acceptance ceiling while retaining the strict
5% result and unchanged isolation/finite-gradient requirements. The segmented
SDPA default remains unchanged pending results. The initial discrepancy does
not establish a kernel defect, training-quality regression, or throughput
disadvantage.

## Gate results

The combined-process native BF16 GQA canary uses 16 query heads, four KV heads,
head dimension 256 and lengths 1, 3, 63, 65, 127 and 129. Against FP32 math
SDPA, forward relative L2 is 0.001818 and dQ/dK/dV errors are
0.002588 / 0.002577 / 0.002250. All are finite and pass the existing
0.02 forward / 0.05 gradient limits.

The ordinary Trainer's eager model packing gate then fails:

| Measurement | Result |
| --- | ---: |
| Independent singleton SDPA loss | 0.9492289424 |
| Packed FA4 loss | 0.9576336741 |
| Adapter gradient relative L2 | 0.0828665942 |
| Unchanged gradient limit | 0.05 |

The loss difference passes its tolerance, but the adapter-gradient difference
does not. The separate original-FLA/FlashQLA diagnostic retains its strict
failure (relative L2 0.152627) and the user's standing `selected_finite`
acceptance. That policy does not override the packing gate. FA4 stops before
compiled packing checks, longest-batch memory preflight, or an optimizer update.

The first failed Trainer invocation raised before writing the complete packing
receipt. The writer now persists `PackingCanaryError.receipt` before propagating
the original exception. A separate bounded replay uses the same frozen inputs
and initial adapters with `canary_only=true`; it cannot perform optimizer
updates even if the eager check unexpectedly passes. Original failed artifacts
are retained without overwriting them.

The replay reproduces the exact losses and gradient error with the same initial
master digest and zero optimizer updates. All repeat, prefix-perturbation and
cross-example input-gradient effects are exactly zero for lengths [1, 3],
[63, 65] and [127, 129]; own-input gradient maxima are nonzero and finite.
Decoder layers 0–2 match exactly. The first difference appears at layer 3,
the first full-attention layer (relative L2 0.001923), accumulating to 0.016090
at layer 31 and 0.019179 at final normalization. This is consistent with
accumulated BF16/backend rounding differences, but does not prove an equivalent
training trajectory.

The user's subsequent instruction accepts the roughly 8% difference and
authorizes continuing. `accepted_config.yaml` records that authority, a bounded
0.10 learning tolerance, reuse of the unchanged successful native receipt,
and separate `b200_bf16_fa4_accepted` output/log directories. Fresh eager and
compiled receipts preserve `passed=false` when the strict 0.05 test fails and
record `accepted_for_learning_comparison` separately. This acceptance is scoped
to the diagnostic continuation; it does not change the default profile.

## Timing limitations and cache preservation

The SDPA control completes 20 updates / 640 examples with verified BF16 bases,
FP32 masters and no quantized modules. Peak allocated memory is 146.995 GiB.
Its final ten updates average 7.78158 seconds, but this is **not a clean warmed
baseline**. The current shared cache lacked many entries from the original
4B systems recipe. Existing compatible entries were merged into it while the
control was running, and completion overlapped the measured window. Retain
every raw update duration; do not derive a speedup or use this control to
promote a candidate. A future comparison needs a completed cache merge before
either condition starts and reverse-order replication if promising.

The merge preserves existing entries and skips locks/temporary files. Its
original receipt and corrected timing interpretation are both retained.
The initial FA4-overlay-first attempt selected TVM FFI 0.1.14.post1, incompatible
with FlashQLA's pinned 0.1.11, and was interrupted before any optimizer update.
The corrected combined process puts FlashQLA's pinned environment first and
appends the FA4 overlay. Both the failed import attempt and successful combined
native canary remain recorded.
